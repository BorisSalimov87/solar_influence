# Solar influence

Исследование связи полного электронного содержания (GEC) ионосферы с площадью
областей, похожих на корональные дыры (CH), по данным 2025 г. Проект ведётся как
хранилище Obsidian: задачи, данные и расчёты связаны в графе по `ontology.yaml`.

## Быстрый старт

Нужен Python 3.12 и окружение `.venv` (pandas, matplotlib, PyYAML). Если окружения
нет, восстановите его из `pyproject.toml` и `uv.lock` командой `uv sync`. Все команды
запускаются из корня проекта.

```bash
# GEC только для моментов из data/holes.csv → data/gec-0km-2025-hours.csv
.venv/bin/python src/build_specific_gec.py

# Проверка результата; ожидаемо FAIL: 2 hole times missing in GEC
.venv/bin/python checks/check.py

# Средний GEC по исходному ряду → 1.5762 TECU
.venv/bin/python src/calc_gec_average.py data/gec-0km-2025.csv

# График GEC → cache/plot/gec.png
.venv/bin/python src/plot_gec.py

# Верификатор HW2: 45 тестов, правило принятия — все проходят
.venv/bin/python -m pytest tests -q
```

`checks/check.py` на текущих данных завершается с кодом 1: в исходном ряду нет всего
дня 2025-11-26. Это известное ограничение, а не ошибка сборки; не интерполировать.

## Данные

| Файл | Содержимое |
|---|---|
| `data/gec-0km-2025.csv` | исходный 15-минутный ряд GEC за 2025 г., 34 944 строки; столбцы `Year Month Day DOY Hour Minute UnixTimestamp uqrg`; `uqrg` — GEC в TECU, время UTC; разделитель — пробел; нет всего дня 2025-11-26 |
| `data/holes.csv` | площадь областей, похожих на CH, 722 строки; столбцы `date,polariz,freq,area_holes`; `area_holes` — безразмерное отношение площади к площади солнечного диска; моменты только 03:00 и 07:00 |
| `data/gec-0km-2025-hours.csv` | производный файл: GEC только для моментов из `holes.csv`, 720 строк; разделитель — пробел; нет 03:00 и 07:00 за 2025-11-26 |

`data/gec-0km-2025-hours.csv` — отфильтрованное подмножество исходного ряда, а не
независимая выборка. Источник исходного GEC в проекте не зафиксирован.

## Документация

- `INDEX.md` — где что лежит.
- `AGENTS.md` — правила работы агента, онтология графа и протокол задач.
- `STATUS.md` — текущее состояние работы.
- `diary.md` — журнал проекта; только дописывается.
- `ontology.yaml` — классы, отношения и правила графа.
- `METHOD.md` — методика верификатора (записана до первого прогона).
- `tests/` — юнит-тесты и верификационные тесты данных; `results/` — прогоны,
  выводы «до»/«после» и окружение; `REPORT.md` — отчёт по HW2.
