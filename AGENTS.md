# AGENTS.md

## 0. Цель и образ результата
Проект: связь полного электронного содержания (GEC) ионосферы с площадью
корональных дыр Солнца. Ближайшая задача — подготовить GEC только для тех
моментов времени, которые есть в data/holes.csv.

В конце работы в проекте существуют:
- `src/build_specific_gec.py` — читает `data/gec-0km-2025.csv` и
  `data/holes.csv`, пишет `data/gec-0km-2025-hours.csv`; запуск из корня:
  `.venv/bin/python src/build_specific_gec.py`;
- `data/gec-0km-2025-hours.csv` — те же столбцы и порядок строк, что у
  источника (`Year Month Day DOY Hour Minute UnixTimestamp uqrg`), только
  строки, чей момент времени (Year-Month-Day Hour:Minute) встречается в
  столбце `date` файла `data/holes.csv`;
- `checks/check.py` — проверка результата.

Ничего больше создавать не надо.

## 1. Критерий готовности
Работа считается выполненной, когда команды завершаются с кодом 0:

```
.venv/bin/python src/build_specific_gec.py
.venv/bin/python checks/check.py
```

Проверка требует: файл результата существует; время каждой строки — 03:00 или
07:00; набор моментов времени результата совпадает с набором `date` из
`data/holes.csv`. Вызови проверку сам перед окончательным ответом.

## 2. Карта проекта и источники

`data/holes.csv` — запятая, столбцы `date,polariz,freq,area_holes`; 722
строки, время только 03:00:00 и 07:00:00, `polariz` и `freq` постоянны
(`I`, `3000`), подгрупп по ним нет. `data/gec-0km-2025.csv` — пробелы,
15-минутный ряд за 2025 год, 34 944 строки, столбцы `Year … uqrg`.
`data/gec-0km-2025-hours.csv` — производный файл этой задачи.

`src/build_specific_gec.py` — фильтр GEC по моментам из `holes.csv`;
`src/plot_gec.py` — график GEC в `cache/plot/gec.png`; `checks/check.py` —
проверка результата, только чтение. `paper/Signature of the coronal hole
near.pdf` и `paper/*.txt` — статья-кейс; `memory/L1.md`–`L3.md` — её сжатие.

### Чего агент не может знать сам

- `area_holes` — безразмерное отношение площади областей, похожих на
  корональные дыры, к площади солнечного диска; значения в файле уже в этой
  шкале, не умножать на 100 и не переводить в Мм² без решения исследователя.
  Это автоматическая оценка «похожих на CH» областей, а не каталог CH.
- `uqrg` — глобальное электронное содержание (GEC) в TECU; это не
  концентрация электронов и не TEC каждого отдельного пункта наблюдения.
- В `data/gec-0km-2025.csv` отсутствует весь день 2025-11-26 (96 отсчётов).
  Поэтому в `data/gec-0km-2025-hours.csv` 720 строк, а не 722: нет 03:00 и
  07:00 этого дня, хотя они есть в `holes.csv`. `checks/check.py` на этом
  красный — это ожидаемо. Не интерполировать, не подставлять соседние дни и
  не дополнять результат; решение принимает человек.
- `memory/L2.md` и `L3.md` — сжатие статьи об апрельском событии 2010 г., а не
  результат по данным 2025 г. Числа и выводы статьи нельзя переносить в
  анализ GEC–CH за 2025 г.
- `UnixTimestamp` и столбцы `Year…Minute` в GEC — UTC; `date` из `holes.csv`
  сопоставляется с ними по календарным полям без пересчёта часовых поясов.
